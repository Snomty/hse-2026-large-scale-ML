# Hadoop Streaming (Python)

## 1) WordCount

**Задача:** по входному тексту посчитать, сколько раз встречается каждое слово.

**Вход:** текстовые строки произвольного текста.

**Выход:** строки вида  
`word <count>`

**Примечания:**  
- Приведи слова к нижнему регистру.  
- Считать “словом” последовательность букв/цифр (без пунктуации).

---

## 2) LineCount (RecordCount)

**Задача:** посчитать общее количество строк во входном файле.

**Вход:** текстовые строки (каждая строка — запись).

**Выход:** одна строка вида  
`lines <count>`  
(или просто число, но выбери единый формат)

---

## 3) Distinct Words

**Задача:** посчитать количество уникальных слов во входном тексте.

**Вход:** текстовые строки.

**Выход:** одна строка вида  
`distinct_words <count>`

**Примечания:**  
- Те же правила токенизации, что и в WordCount (lowercase, без пунктуации).

---

## 4) Top-N Words (2-pass)

**Задача:** найти топ-N самых частых слов.

**Вход:** текстовые строки.

**Выход:** N строк вида  
`word <count>`  
от более частых к менее частым (если частоты равны — порядок на твой выбор, но опиши правило).

**Примечания:**  
- N задаётся параметром (например, через переменную окружения или константу в коде для урока).  
- Разрешается решать в два MapReduce-прохода.

---

## 5) Reduce-side Join (2 datasets by key)

**Задача:** объединить два датасета по общему ключу `user_id`.

**Вход:** два входных файла:
- **users.tsv**: `user_id<TAB>name<TAB>country`
- **events.tsv**: `user_id<TAB>timestamp<TAB>event_type`

**Выход:** для каждого события вывести “обогащённую” строку:
`user_id<TAB>name<TAB>country<TAB>timestamp<TAB>event_type`

**Примечания:**  
- Если для события нет пользователя — событие можно пропускать или выводить с пустыми полями (выбери поведение и опиши).  
- Если для одного user_id несколько строк users (ошибка данных) — опиши, как обрабатываешь.

---

## 6) Sessionization by user_id

**Задача:** по событиям пользователей посчитать количество сессий на пользователя.  
Сессия — последовательность событий, где разрыв между соседними событиями не превышает `SESSION_GAP` минут. Если разрыв больше — начинается новая сессия.

**Вход:** **events.tsv**:  
`user_id<TAB>timestamp<TAB>event_type`

**Выход:** строки вида  
`user_id<TAB>sessions_count`

**Примечания:**  
- timestamp в формате ISO-8601 или epoch seconds (выбери формат для урока и зафиксируй).  
- Входные события могут быть не отсортированы по времени.  
- SESSION_GAP (например, 30 минут) задаётся параметром.

---

## 7) Histogram / Bucketing (distribution)

**Задача:** построить гистограмму по времени ответа `response_time_ms`.

**Вход:** **requests.tsv**:  
`request_id<TAB>response_time_ms`

**Выход:** строки вида  
`bucket_label<TAB>count`

**Примечания:**  
- Придумай и зафиксируй набор бакетов, например:  
  - `0-10`, `10-50`, `50-100`, `100-500`, `500-1000`, `1000+`  
- Значения на границах должны попадать в понятные интервалы (опиши правило).

---

## 8) Последнее действие пользователя (Latest-by-user via secondary sort)

**Задача:** для каждого `user_id` найти его последнее действие по времени.

**Вход:** **events.tsv**:  
`user_id<TAB>timestamp<TAB>event_type`

**Выход:** строки вида  
`user_id<TAB>timestamp<TAB>event_type`  
где `timestamp` — максимально возможный для данного user_id.

**Примечания:**  
- Вход не отсортирован.
